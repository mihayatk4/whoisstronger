# Who's Stronger? — первая версия

Ежедневная игра про схватки персонажей. Обычный статический сайт: HTML, CSS и JavaScript без сборки и без зависимостей.

## Как открыть

Дважды кликнуть `index.html` — сайт работает прямо из файла.

Либо запустить локальный сервер из этой папки и открыть http://localhost:5173:

```bash
python -m http.server 5173
```

Сбросить свой прогресс во время тестов: открыть адрес с `#/reset` на конце (работает только на своём компьютере).

## Персонажи: таблица

Все 100 персонажей лежат в одной таблице `data/characters.csv`. Одна строка = один персонаж.

**Как править в Google Таблицах**

1. Google Таблицы → Файл → Импорт → Загрузить → выбрать `data/characters.csv`.
2. Править что угодно. Колонка `reviewed` для себя: ставьте `yes`, когда проверили персонажа.
3. Файл → Скачать → CSV. Сохранить поверх `data/characters.csv`.
4. Пересобрать файлы игры:

```bash
node tools/build-data.js
```

Скрипт проверит таблицу (пустые поля, тир 1–6, статы 1–100, повторы id и имён). Если есть ошибки, он ничего не запишет и покажет, в какой строке проблема.

**Колонки**

| Колонка | Что это |
| --- | --- |
| `id` | Короткий код латиницей без пробелов: `goku`, `ironman`. Не меняйте у существующих |
| `name`, `universe`, `group` | Имя, вселенная, группа (Anime / Marvel / DC / Invincible / The Boys / Other) |
| `tier` | 1 Street, 2 City, 3 Country, 4 Planet, 5 Star, 6 Universe |
| `strike` … `abilities` | 7 параметров, 1–100 |
| `color1`, `color2` | Цвета фона портрета, если нет картинки |
| `img`, `img_pos` | Картинка (можно оставить пустым, см. ниже) и какая часть остаётся в квадрате, например `50% 30%` |
| `description` | Одна строка под именем |
| `powers` | Способности через `;` |
| `feat1`…`feat3` + `_source` | Подвиги и откуда они |
| `emoji` | 3 эмодзи — подсказка 2 в угадайке |
| `weapon` | Фирменное оружие или предмет — подсказка 4 |
| `rival` | Главный соперник — подсказка 5 |
| `hint_association`, `hint_ability`, `hint_fact` | Подсказки 1, 3 и 6 |
| `role` | Hero / Villain / Anti-hero — сравнивается после неверной попытки |
| `power_source` | Alien, God, Trained human, Superpowered, Inner energy, Tech, Magic, Monster — тоже для сравнения |
| `guessable` | `yes` — персонаж узнаваемый и может быть загаданным в угадайке |
| `difficulty` | easy / medium / hard — насколько сложно угадать, показывается в угадайке |

**Добавить персонажа** — новая строка в таблице и `node tools/build-data.js`.

Расписание дней строится от списка персонажей, поэтому после изменений прошлые дни в архиве тоже меняются. Перед запуском расписание стоит зафиксировать.

## Бои дня: таблица матчапов

Бои на каждый день пишутся заранее в `data/matchups.csv`. Одна строка = один бой. Вердикт и объяснение берутся отсюда, а не из формулы.

| Колонка | Что это |
| --- | --- |
| `day` | Номер дня: 1 = дата `scheduleStart` в `js/config.js`, 2 = следующий день и т.д. В каждом дне 5 боёв |
| `a`, `b` | id бойцов (левый и правый). Последний бой дня — босс |
| `winner`, `pct` | Кто побеждает и с каким шансом (50–99) |
| `factor1`…`factor3` | 3 ключевых фактора — короткие чипы |
| `start`, `turning_point`, `finish` | Ход боя в три шага |
| `underdog_path` | Как может победить проигравший — повод поспорить |
| `reviewed` | Для себя: `yes`, когда проверили |

Правка — так же, как с персонажами: Google Таблицы → скачать CSV поверх файла → `node tools/build-data.js`. Скрипт проверит, что id существуют, победитель — один из двух, пары не повторяются, и предупредит, если персонаж выходит слишком часто или разница тиров больше одного.

Когда дни из таблицы заканчиваются, игра сама генерирует бои по формуле (с короткими автоматическими объяснениями). Чтобы этого не случилось, добавляйте новые дни заранее.

## Картинки персонажей

Положите картинку в `assets/characters/` с именем как `id`: `vegeta.jpg`, `batman.png`, `gojo.webp`. Запустите `node tools/build-data.js` — скрипт найдёт её сам. Колонку `img` в таблице заполнять не нужно.

Картинка сама обрежется до квадрата. Пока её нет, показываются инициалы на цветном фоне. Лучше всего смотрятся картинки от 400×400 на тёмном фоне или без фона.


**Аниме — автоматически с AniList.** Скрипт ищет персонажа, проверяет, что он из нужного сериала, скачивает картинку и записывает в таблицу `img`, `img_source` (страница на AniList) и `img_date`:

```bash
node tools/fetch-anilist.js
```

Варианты: `--dry` (только показать, что найдено), `--only=gohan,kidbuu` (только эти), `--force` (заменить уже скачанные). Если имя на AniList другое, добавьте его в список `SEARCH` в начале скрипта. После скрипта: `node tools/build-data.js`.

Картинки AniList — официальные арты правообладателей. Источник в таблице помогает с указанием авторства, но не даёт прав на картинку. Перед запуском с рекламой проверьте условия API AniList.

**Marvel, DC, Star Wars, Godzilla — из открытой базы супергероев** (github.com/akabab/superhero-api). Соответствия персонажей прописаны вручную в списке `MAP` в начале скрипта:

```bash
node tools/fetch-superheroes.js
```

Те же варианты: `--dry`, `--only=batman`, `--force`. В базе нет Invincible, The Boys, Voldemort и John Wick — их картинки нужно искать вручную. Это тоже арты правообладателей.

## Кто кого побеждает

- **Шанс победы считается по рейтингу силы** (колонка `power` в `data/characters.csv`, 100–1000), как Эло в шахматах: 35 очков разницы ≈ 60%, 100 ≈ 76%, 150 (соседний тир) ≈ 85%. Статы — только для полосок и Higher or Lower.
- **Каждому тиру свой диапазон рейтинга:** Street 100–249, City 250–399, Country 400–549, Planet 550–699, Star 700–849, Universe 850–1000.
- **Какую версию оцениваем:** аниме — пиковую в аниме и манге; Marvel, DC, The Boys, Invincible — версию из фильма или сериала, если она есть.
- **Бои дня** берутся только из пар, где шанс фаворита от 60 до 92% (`dailyMinFav`, `dailyMaxFav` в `config.js`): никаких 52/48 и никаких 97/3.
- **Бои из таблицы матчапов судятся как настоящие бои:** оружие, способности, контры. Их вердикт (`winner`, `pct`) важнее голого рейтинга: Saitama успевает раньше щелчка Таноса, Manhattan разбирает Frieza на атомы. Сборка печатает список боёв, где способности меняют исход, а в игре под вердиктом появляется строка «On raw power… Abilities flip this fight».
- **Весь рейтинг одной таблицей:** `POWER.md`.
- **Сверка с VS Battles Wiki:** `node tools/check-vsbw.js` → `data/vsbw-report.csv`. Это второе мнение: вики часто завышает тир из-за оружия и разовых форм.

## Очки

Все числа — в `js/config.js` → `scoring`, `sliderWeek`, `ranks`.

- **5 боёв в день, максимум 1000.** Верные выборы подряд дают множитель ×1 → ×1,5 → ×2 → ×2,5 → ×3 (100, 150, 200, 250, 300).
- **Ошибка** отнимает «разрыв × текущий множитель» (83:17 при ×2 → −132), серия сбрасывается. На спорной паре (разрыв до 10) серия сохраняется.
- **Ползунок:** игрок ставит шанс левого бойца. Ошибка до ±1% считается попаданием (полные очки). Дальше очки = S × (1 − (ошибка−1)/29)^2,5, от ошибки 30% и больше — 0. S = 300 (один ползунок в день) или 275 (два). Примеры при S=300: ±2 → 275, ±3 → 251, ±5 → 207, ±10 → 118, ±20 → 21. Ползунок не влияет на серию.
- **Сколько ползунков в день** — по дню недели (`sliderWeek`, начиная с воскресенья): вс 2, пн 1, вт 1, ср 0, чт 1, пт 1, сб 2. Места ползунков случайные, но одинаковые у всех.
- **Счёт дня не ниже 0.** Угадайка считается отдельно (до 100), в счёт дня и ранг не входит.
- **Ранг** — сумма очков боёв за все дни (Mortal → Absolute). **Серия дней** растёт, если все бои дня сыграны в этот день. Один пропуск в неделю прощается (`streakFreeze`).

## Запуск на whoisstronger.org

Название остаётся **Who's Stronger?**, домен — `whoisstronger.org` (`siteUrl` в `js/config.js`, ссылки в `index.html`, `privacy.html`, `robots.txt`, `sitemap.xml`).

### Перед запуском

1. **Дата запуска.** В `js/config.js` поставьте `launchDate` = день запуска (сейчас `2026-11-17`). С этого дня считается «Day #1» и начинается архив. Меняйте до запуска: после — прошлые дни перемешаются.
2. **Бои.** Расписание вручную идёт до 2026-12-07 включительно. Дальше нужна новая партия в `data/matchups.csv`.
3. **Почта для связи.** На `privacy.html` указан `contact@whoisstronger.org`. Включите в Cloudflare **Email Routing** (бесплатно): домен → Email → Email Routing → пересылка `contact@` на вашу почту.

### Публикация (Cloudflare Workers)

Проект уже подключён: Cloudflare → Workers & Pages → **whoisstronger** берёт код из GitHub и при каждой загрузке запускает `npx wrangler deploy`. Настройки — в `wrangler.jsonc`; что НЕ попадает на сайт — в `.assetsignore` (таблицы, скрипты, README, исходники картинок).

1. **Первый запуск** проходит без базы: игра работает, вместо процентов игроков — «Not enough votes yet».
2. **База голосов (D1).** Cloudflare → Storage & Databases → D1 → Create → имя `whoisstrongest`. Откройте её → **Console** → вставьте всё из `db/schema.sql` → Execute. Скопируйте **Database ID** (вверху страницы базы).
3. **Подключите базу.** В `wrangler.jsonc` уберите `//` перед блоком `d1_databases` (7 строк) и вставьте свой ID вместо `PASTE-YOUR-DATABASE-ID-HERE`. Загрузите на GitHub — Cloudflare сам пересоберёт. (Привязку через сайт Cloudflare не делайте: при следующей сборке её перезапишет `wrangler.jsonc`.)
4. **Домен.** Worker whoisstronger → Settings → **Domains & Routes** → Add → Custom domain → `whoisstronger.org`, затем ещё раз для `www.whoisstronger.org`. Домен должен быть в вашем аккаунте Cloudflare (куплен там или DNS перенесён через Add a site).
5. **Аналитика (без cookies).** Cloudflare → Analytics & Logs → **Web Analytics** → Add a site → `whoisstronger.org` → автоматическая установка. Либо скопируйте токен в `analyticsToken` в `js/config.js`.

### Проверка после запуска

- Откройте сайт с телефона, сыграйте день. Сначала вместо процентов игроков будет «Not enough votes yet» — они появятся после 30 голосов за бой (`minVotesToShow`), «лучше X%» — после 20 игроков за день.
- Проверка сервера: `https://whoisstronger.org/api/vote` в браузере должен ответить `{"error":"POST only"}`. Если в игре всё ещё «Not enough votes yet» после многих голосов — проверьте шаг 3 (база подключена).
- Превью ссылки: вставьте адрес в Telegram/Discord — должна появиться картинка Goku vs Superman. Если кеш старый — проверьте на opengraph.xyz.
- Search Console (Google): добавьте сайт и отправьте `https://whoisstronger.org/sitemap.xml`.

### Админка (статистика игроков)

`https://whoisstronger.org/admin` — игроки по дням, сколько дошло до конца, новые и вернувшиеся, в какие часы играют, голоса за каждый бой дня, ответы на ползунке и распределение очков.

Вход по секретному ключу. Задаётся один раз: Cloudflare → Workers & Pages → **whoisstronger** → Settings → **Variables and Secrets** → Add → тип **Secret**, имя `ADMIN_KEY`, значение — длинный пароль (20+ символов). Ключ хранится только в Cloudflare, в код и на GitHub он не попадает. Сменить ключ — поменять значение там же.

На localhost страница `admin.html` показывает демо-цифры. Код: `admin.html` и `worker/api/admin.js`.

### Обновления

Изменили что-то → загрузили на GitHub → Cloudflare сам опубликует за минуту. Скрипты и стили не кешируются надолго (`_headers`), поэтому игроки получают новую версию при следующем заходе.

Новые фото персонажей: положите в `assets/characters`, затем `npm install --no-save sharp`, `node tools/optimize-images.js`, `node tools/build-data.js`.
